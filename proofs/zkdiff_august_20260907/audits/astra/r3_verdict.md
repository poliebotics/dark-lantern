1. **REVISE: the declared scale map differs from execution.** Pooling, interpolation and attention inherit their input scale, overriding seven `ftab` entries:

   | Tensor | Declared `f` | Executed `f` |
   |---|---:|---:|
   | `pool.2`, `pool.3`, `up.0`, `up.1` | 12 | 11 |
   | `down_attns.3.attn` | 13 | 11 |
   | `mid_attn.attn` | 13 | 12 |
   | `up_attns.0.attn` | 12 | 11 |

   A port driven by `ftab` can therefore produce different values. Publish one effective scale map and make every manifest agree with it. The executed histogram is `{8:1, 9:21, 10:26, 11:89, 12:40, 13:5, 14:6}`. README.md:196 (on-box: `oracle/README.md` line 196), `oracle/int_ref.py` line 368.

2. **REVISE: distinguish conversion rounding from runtime rounding.** Inputs, weights, constants and LUT construction use **ties-to-even**; runtime shifts and divisions use **ties toward positive infinity**. This distinction changes existing vectors: d2/1328 has six noise elements and four E elements where the rules disagree, including `−5577.5 → −5578` and `96.5 → 96`. State both rules explicitly, including exact left shifting when `rshift_round` receives `s≤0`. Rust should import the frozen constants and tables rather than regenerate transcendental results. `oracle/int_ref.py` line 265, `oracle/int_ref.py` line 302, `oracle/kernels.py` line 24.

3. **REVISE: reconcile the admitted domain and saturation policy.** `clamp16` permits `−32768`, but convolution and vector export reject it through `abs(x)≤32767`. The convolution bound likewise assumes 32767. Also, input clipping and clipped activation-LUT entries bypass the saturation counter. Thus “every saturation is counted” is false generally. Independent checks found **zero input clips** across the reported inputs, so this does not invalidate those scores. Define full-range acceptance or explicit rejection consistently, and count every clipping event if saturation remains a failure criterion. `oracle/kernels.py` line 69, `oracle/int_ref.py` line 304, `oracle/int_ref.py` line 320, `oracle/kernels.py` line 205.

4. **ACCEPT: the current integer kernels are mathematically coherent.** GroupNorm’s biased statistics, quantised epsilon, six extra mean bits, floor division, Newton initialisation/termination and affine rounding match the implementation. The activation domains cover all int16 inputs. Attention correctly implements `/4`, clamps the exponent index and guarantees a positive denominator through `EXP[0]=2²⁰`. Bilinear uses clamped borders and one rounding after both axes; pooling rounds its four-element sum once. Scalar/vector self-tests pass. Add explicit tie, endpoint, constant-GroupNorm and border fixtures to complement the small random tests. `oracle/kernels.py` line 39, `oracle/kernels.py` line 144, `oracle/kernels.py` line 228, `oracle/kernels.py` line 296.

Recomputing with the full-domain factor **32768** gives maximum accumulator bounds **406,605,889,536** for int16 and **1,576,206,336** for int8. The largest conservative int16 requantisation expression is **3,739,957,335,765,942,272 < 2⁶³**.

   Before removing checks, bind bounds to the authenticated constants, shapes and admitted ranges for convolution/requantisation; attention dot products, differences, denominator and weighted numerator; GroupNorm sums, variance numerator and affine products; noising/rescaling; pooling/bilinear; SSE and paired aggregation. These justify i64 accumulation with operands widened before multiplication; retain u128 for GroupNorm’s squared numerator/division/root. Runtime linears are already folded into constants. `oracle/int_ref.py` line 293, `oracle/kernels.py` line 159, `oracle/int_ref.py` line 374.
