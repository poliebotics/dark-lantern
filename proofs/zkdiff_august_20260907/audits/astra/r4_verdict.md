The existing release test binary passes **17/17 tests**. The audit found defects that those four vectors do not expose.

1. **REVISE: arbitrary-input parity is false against the current oracle.** The chained and isolated tests substantiate all 188 outputs per fixture, the four residual sums, and the mutation detector. They do not establish universal equivalence. A concrete admitted-input counterexample is `C = noise = −32767`: noising produces **−39795 before clipping**; Python returns **−32768**, while Rust returns **−32767**. The current Python contract admits the full int16 range. Reconcile that contract before adding fixtures. `source/armc-int/tests/parity.rs` line 75, Rust kernels.rs:82 (`source/armc-int/src/kernels.rs` line 82), Python kernels.py:84 (`oracle/kernels.py` line 84).

2. **REVISE: LUT clipping events are missed.** Rust’s `lut_apply` has no saturation counter. I checked that Python regenerates the existing SiLU 11→12 and 10→11 tables byte-for-byte; they contain **16,378 and 16,384 clipped entries**. Input `32767` returns `32767`, but Python counts one clipped-table hit and Rust counts zero. Export and authenticate a clipping mask alongside each table, then count indexed hits. The Python exporter currently saves the number of clipped entries, without the mask. `source/armc-int/src/kernels.rs` line 465, `oracle/int_ref.py` line 363, `oracle/int_ref.py` line 591.

3. **REVISE: the tested artifact is superseded, and the advertised FINAL override does not work unchanged.** G1 now designates `final/` as authoritative. Its filenames include session/row, manifests use `scale_map`, and arrays include float32 noise records and native int8 weights. The exporter expects old filenames and only int16/int64 arrays; the loader requires `ftab`. Tests also hardcode old residuals, hashes, scale discrepancies and accumulator maxima. Update the transport and make expectations specific to the frozen artifact. G1 README.md:10 (on-box: `oracle/README.md` line 10), `source/tools/export_oracle.py` line 24, `source/armc-int/src/loader.rs` line 120, `source/armc-int/tests/parity.rs` line 324.

4. **REVISE: add differential boundary fixtures; no new numerical theory is needed.** Generate expected bytes **and clipping counters** from the reconciled Python scalar oracle. Cover signed ties and their neighbours at every used shift/divisor; zero and negative shifts; both domain endpoints; positive/negative saturation in noising, convolution, add, concat and GN; constant and nearly constant GN groups, balanced endpoints and maximum group size; square-root perfect squares ±1; convolution corner/edge impulses and stride-1/2 tails; pooling ties and bilinear borders with one final rounding; every LUT index/mask; equal-score attention, exponent-clamp boundaries and signed weighted averages; endpoint SSE. The current synthetic 3×3 comparison cases all have output width ≤7, so **none tests the eight-column block against the generic implementation**. Preserve randomized and full-network comparisons too. These strengthen evidence; universal equivalence still requires reviewing each operation and its bounds. `source/armc-int/tests/parity.rs` line 245, `oracle/kernels.py` line 399.

5. **ACCEPT for the reviewed constants: convolution’s unchecked arithmetic has a valid static justification.** Independent calculations from hash-checked constant arrays reproduce **406,605,889,536 / 1,576,206,336**, and the largest int16 requantisation bound is **3,739,957,335,765,942,272 < 2⁶³**. `finalize()` recomputes `32768 × max Σ|W|` and rejects an excessive requantisation bound. This covers every partial sum for every int16 input, including adversarial signs. The final accumulator assertion is supplementary; checking a wrapped result alone would not prove safety. GN’s 60/99/55-bit bounds and the stated SSE ceiling also reproduce. However, some GN bounds are fixture-time checks, and the source uses wrapping arithmetic in GN statistics and convolution epilogues too. Bind the reviewed constants and geometry before carrying this argument into the proof. `source/armc-int/src/kernels.rs` line 159, `source/armc-int/src/kernels.rs` line 240, `source/armc-int/tests/parity.rs` line 346.

6. **REVISE before proving: execution is deterministic, but the intended relation is unbound.** Little-endian decoding, exact input lengths and common C/noise across both passes are present. I found no nondeterministic arithmetic. Nevertheless, the blob and both conditionings are private; public values contain only two residuals, saturation count and qmax. Host-printed hashes do not bind the proof. The full guest must compute the constants digest over all weights, effective scales, folded biases, GN parameters, tables/masks and coordinates; bind the arithmetic-spec version through the approved ELF/vkey; and require the verifier to check those expected identifiers. It must derive or authenticate C, noise and both conditionings, including row identities and the permitted offset, and enforce the chosen saturation policy. bench main.rs:43 (on-box: `source/armc-eval-bench/program/src/main.rs` line 43), bench main.rs:82 (on-box: `source/armc-eval-bench/program/src/main.rs` line 82).

   Parsing alone does not establish valid arithmetic semantics: scales up to 62 are accepted, while raw `i64 <<` can discard significant bits despite overflow checks. For example, `rshift_round(32767,−62)` becomes negative. Authenticate the reviewed blob or validate representability before such shifts. `source/armc-int/src/blob.rs` line 180, `source/armc-int/src/kernels.rs` line 64, [Rust overflow rules](https://doc.rust-lang.org/reference/expressions/operator-expr.html#overflow).
